# Вимоги до застосунку TaskFlow

## 1. Загальна характеристика

Назва застосунку: TaskFlow.

TaskFlow - локальний застосунок для керування особистими завданнями. Система призначена для створення, редагування, впорядкування та контролю виконання завдань.

Застосунок розробляється мовою Python із використанням бази даних SQLite. На початковому етапі взаємодія з користувачем здійснюється через інтерфейс командного рядка (CLI).

## 2. Цільові користувачі

Застосунок орієнтований на студентів, розробників та інших користувачів, яким необхідно впорядковувати повсякденні завдання і відстежувати їх виконання.

## 3. Функціональні вимоги

FR-01. Створення нового завдання із зазначенням назви та опису.

FR-02. Перегляд списку всіх збережених завдань.

FR-03. Редагування назви, опису та інших параметрів завдання.

FR-04. Видалення вибраного завдання.

FR-05. Установлення пріоритету завдання: низький, середній або високий.

FR-06. Установлення кінцевого терміну виконання завдання.

FR-07. Зміна статусу завдання: заплановано, у процесі, виконано.

FR-08. Пошук і фільтрація завдань за статусом або пріоритетом.

FR-09. Перегляд статистики за кількістю виконаних і невиконаних завдань.

FR-10. Збереження завдань у локальній базі даних SQLite.

## 4. Нефункціональні вимоги

NFR-01. Застосунок має працювати локально без постійного підключення до Інтернету.

NFR-02. Дані користувача повинні зберігатися між запусками програми.

NFR-03. Програмний код має бути поділений на окремі модулі відповідно до їхньої відповідальності.

NFR-04. Основні функції застосунку мають перевірятися автоматизованими тестами.

NFR-05. Програма повинна коректно обробляти помилкове введення користувача.

NFR-06. Розробка має здійснюватися з використанням Git для контролю версій.

## 5. Технологічний стек

Мова програмування: Python 3.

База даних: SQLite.

Інтерфейс користувача: CLI.

Тестування: pytest.

Контроль версій: Git, GitHub.

Середовище розробки: Visual Studio Code.

## 6. Попередня архітектура

Застосунок складатиметься з таких логічних компонентів:

- CLI - взаємодія з користувачем.
- Task Service - операції над завданнями.
- Task Model - структура даних завдання.
- Repository - збереження й отримання даних із SQLite.
- Statistics Service - обчислення статистики завдань.

Взаємодія компонентів здійснюватиметься через визначені інтерфейси, щоб спростити тестування та подальше розширення програми.

## 7. Критерії успішного виконання

Застосунок вважається працездатним, якщо користувач може створити завдання, зберегти його, переглянути, відредагувати, змінити статус та видалити.

Дані повинні залишатися доступними після повторного запуску програми. Основна бізнес-логіка має успішно проходити автоматизовані тести.
