# ЗАВДАННЯ

## 1. Застосунок

Назва: TaskFlow.

TaskFlow - локальний застосунок для керування особистими завданнями.

Основні можливості:
- Створення, перегляд, редагування та видалення завдань.
- Установлення пріоритетів і термінів виконання.
- Зміна статусів завдань.
- Пошук і фільтрація.
- Перегляд статистики виконання.
- Збереження даних між запусками програми.

Технологічний стек:
- Python 3
- SQLite
- pytest
- Git та GitHub

Повні вимоги описано в docs/app-requirements.md.

## 2. Обрана агентна IDE

Visual Studio Code з GitHub Copilot.

Інструмент обрано через підтримку MCP, агентного режиму, проєктних інструкцій, skills та інтеграції з GitHub.

## 3. Мета Agent Harness

Створити інфраструктуру, яка дозволить ШІ-агенту допомагати з розробкою TaskFlow, використовувати актуальні знання про застосунок та дотримуватися визначених правил безпеки.

## 4. Цільові задачі агента

1. Генерація програмних модулів відповідно до архітектури TaskFlow.
2. Створення автоматизованих тестів із використанням pytest.
3. Перевірка програмного коду на помилки та відповідність вимогам.
4. Оновлення бази знань Obsidian через MCP-конектор.
5. Аналіз помилок програми та результатів тестування.

## 5. Джерела даних

- Документація застосунку.
- Вихідний код.
- GitHub та історія комітів.
- База знань Obsidian.
- Результати автоматизованих тестів.

## 6. Обмеження дій агента

Allow:
- Читання файлів.
- Аналіз програмного коду.
- Пошук інформації.
- Перегляд результатів тестування.

Warn / Require Approval:
- Зміна існуючого коду.
- Видалення файлів.
- Зміна архітектури.
- Виконання комітів та push.

Block:
- Видалення репозиторію.
- Примусовий push у захищену гілку.
- Видалення історії архітектурних рішень.
- Публікація секретних ключів.

## 7. Організація проєкту

Для виконання практичних робіт використовуються два окремі репозиторії:

1. taskflow-app - застосунок та Agent Harness.
2. taskflow-knowledge-base - база знань Obsidian.

Повні вимоги до інфраструктури наведено в docs/harness-requirements.md.
