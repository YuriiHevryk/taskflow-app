
# TaskFlow RAG — Evaluation Questions

## Purpose

Порівняти якість звичайного текстового та семантичного пошуку в базі знань TaskFlow.

Для обох реалізацій search_notes використовуються однакові запитання.

## Questions

### Q01 — Task Model
Які основні поля має завдання в TaskFlow і що вони означають?

### Q02 — Task Status and Priority
Які статуси та пріоритети завдань описані в базі знань TaskFlow?

### Q03 — SQLite Architecture
Чому для локального зберігання завдань обрано SQLite?

### Q04 — Component Responsibilities
Чим відрізняються обов'язки Task Service і Task Repository?

### Q05 — Task Creation Flow
Як взаємодіють модель, сервіс і репозиторій під час створення нового завдання?

### Q06 — MCP Connector
Як GitHub Copilot отримує доступ до нотаток Obsidian через MCP?

### Q07 — Guardrails
Що необхідно зробити перед записом нової архітектурної нотатки в Obsidian?

### Q08 — User Settings Storage
Чому налаштування користувача вирішили зберігати в JSON, а завдання — у SQLite?

### Q09 — Application Architecture
Які основні компоненти архітектури TaskFlow та як вони пов'язані?

### Q10 — Missing Decision
Чи є в базі знань затверджене рішення використовувати SQLite Backup API для резервного копіювання TaskFlow?

Якщо підтверджувальної нотатки немає, потрібно прямо вказати, що рішення не знайдено.

## Evaluation Rules

Для кожного запитання:
1. Викликати search_notes з незмінним текстом запитання.
2. Записати знайдені нотатки або фрагменти.
3. Сформувати відповідь лише на основі MCP-результатів.
4. Вказати джерела інформації.
5. Якщо підтвердження немає, не вигадувати відповідь.

## Scoring

0 — релевантну інформацію не знайдено.

1 — інформацію знайдено частково.

2 — знайдено достатню інформацію для правильної відповіді з підтвердженням джерелами.

Максимальний результат: 20 балів.

## Comparison

Після оновлення search_notes порівняти:

- Релевантність знайдених нотаток.
- Точність відповіді.
- Наявність джерел.
- Кількість непідтверджених тверджень.
- Сумарний бал.
- Час виконання, якщо він вимірювався.
